# 요구사항 — 시계탑 퍼즐 (clocktower-puzzles)

> 2026-08-27 설계 인터뷰(그릴링 세션)에서 합의된 내용. 변경 시 이 문서를 갱신한다.

## 1. 프로젝트 목적

- 보드게임 **Blood on the Clocktower**(시계탑에 흐른 피)의 **상황 추리 퍼즐**을 웹에서 풀 수 있는 공개 사이트.
- 1차 대상: 심심풀이로 퍼즐을 풀고 싶은 사람. 계정 없이 URL만으로 접속.
- 장기 방향: **퍼즐 모듈 자체의 고도화**. 텔러(스토리텔러) 보조 웹앱으로 넓히는 계획은 2026-08-27에 접었다 —
  솔버는 퍼즐 검증이라는 본래 목적에 집중하고, 확장은 푸는 경험(좌석 표시·역할 추측, 해설 등) 쪽으로 간다.
- 비공식 팬 프로젝트임을 명시한다 (The Pandemonium Institute 공식 아트/아이콘 사용 금지, 소개 페이지에 고지문).
  - 저장소 차원의 고지는 [NOTICE](../NOTICE)에 정리한다 — 상표, 아트워크 미사용, 규칙 인용 범위,
    공식 번역 출처, 이용자 제작 콘텐츠 책임 소재. 코드는 [LICENSE](../LICENSE)(MIT)로 제공하되
    제3자 콘텐츠는 적용 대상에서 제외한다.

## 2. 퍼즐 콘텐츠

### 2.1 형식: 공개 주장 기반 상황 추리
- 모든 플레이어(생존자)가 자신의 역할과 밤 정보를 **공개 주장**한 상황을 제시한다.
- 악역·술꾼 등은 거짓 주장이 가능하다. 풀이자는 "어떤 배정(그리모어)이어야 전체 주장이 정합적인가"를 추리한다.
- **다일차 타임라인** 지원: 처형·사망 이벤트, "N일차 밤에 본 정보" 표현 가능.
- 좌석명은 현실 이름 대신 **알파벳(A, B, C, …)**. 좌석 순서 = 배열 순서(원형 인접 판정에 사용).
- **역할 풀 = 그 문제의 대본이고 풀이자에게 공개한다** (2026-08-27 결정). 실제 게임에서도 대본은
  공개 정보이고, 풀이자가 좌석에 역할 토큰을 놓아 가설을 세우려면 고를 목록이 있어야 한다.
  따라서 풀은 **좌석 수보다 넉넉해야 한다** — 7자리에 7종이면 대본 자체가 정답을 알려준다.
  수록 문제는 유일해를 유지하는 한도까지 풀을 넓혀 둔다(현재 12~20종).

### 2.2 풀이 상호작용
- 문제마다 **단계형 서브 질문** 배열 (예: "데몬은 누구인가?" → "술꾼은 누구인가?").
- **무제한 재시도**, "포기" 버튼 제공. 정답 또는 포기 전까지 해설 잠금.
- **힌트 최대 2개** (클릭해서 열람, 안 쓴 문제는 비워둠).
- 해설은 **단계별 추론 워크스루** (①, ②, … 논리 사슬).

### 2.3 초기 볼륨과 분류
- 출시 시 **10문제**: 쉬움 3(TB) + 보통 3(TB) + 어려움 4(SV/BMR 역할 혼합).
- 태그: 난이도(easy/normal/hard), 에디션(tb/bmr/sv/mixed), 인원수.
- 에디션 범위: 공식 3에디션 (Trouble Brewing, Bad Moon Rising, Sects & Violets). 실험 캐릭터는 추후.

### 2.4 지원 역할 (솔버가 모델링하는 역할만 퍼즐에 등장 가능)
- TB 정보 역할: Washerwoman, Librarian, Investigator, Chef, Empath, Fortune Teller, Undertaker, Ravenkeeper
- TB 행동·구성 역할 (2026-08-27 추가): Monk(보호 행동), Soldier(킬 면역), Saint(처형 제약), Mayor(구성 전용), Butler(기상 전용)
- TB 교란원·악역: Drunk, Recluse, Poisoner, Spy, Baron, Scarlet Woman, Imp
- SV/BMR 정보: Clockmaker, Seamstress, Juggler, Mathematician, Chambermaid, Dreamer, Oracle, Grandmother, Sage(악마 킬 사망 시 정보)
- BMR 킬 계열 (2026-08-27 추가 — 한 밤 다중 사망은 이들로만 성립): Exorcist(악마 봉쇄), Assassin(1회 확정 킬), Godfather(외부인 ±1 + 외부인 처형 후 의무 킬)
- BMR 죽음 역학 (2026-08-27 2차): Gambler(오답 사망), Tinker(재량 사망), Minstrel(하수인 처형 → 전원 취함 밤), Tea Lady(이웃 보호), Fool(첫 죽음 회피)
- SV 취함 원천 (2026-08-27 3차): Sweetheart — 죽는 순간부터 1명이 계속 취한다. 사망 시점이
  이벤트로 고정돼 취함 대상 1명만 열거하면 되고(사망 순간 중독으로 미발동인 분기 포함),
  대상이 독살범이면 그 이후의 독은 듣지 않는다.

미룬 역할과 이유 (구현 전 논의 필요):
- Virgin, Slayer, Gossip — **낮 공개 행동(지명·총격·발언) 이벤트 모델**이 없다. 이벤트 스키마·에디터·공유 코덱 확장이 선행돼야 한다.
- Flowergirl, Town Crier — 투표·지명 기록이 필요해 위와 같은 확장에 묶인다.
- Courtier, Sailor, Innkeeper, Goon — 독살범 외의 **추가 취함 원천**이 밤마다 움직인다. 탐색 공간이
  밤당 곱으로 늘어 솔버 구조 변경이 필요하다 (같은 계열이던 Sweetheart는 사망 후 1명 고정이라 열거로 해결 — 3차에서 구현).
- Pacifist, Devil's Advocate, Professor, Mastermind — "처형됐지만 죽지 않음"·부활 이벤트 형태가 없다.
- Snake Charmer, Philosopher, Pit-Hag, Barber — **역할이 게임 중 바뀐다**. 배정 고정 전제를 깬다.
- 임프 외 데몬 (Zombuul, Pukka, Shabaloth, Po, Fang Gu, Vigormortis, No Dashii, Vortox) — 데몬별 킬 패턴·정보 왜곡이 엔진 일반화를 요구한다. Vortox(마을 정보 전부 거짓)는 그중 가장 가치 있는 후보.

솔버 모델 경계 (문서화된 근사, `timeline.ts` 참조): 같은 밤 승계 직후의 새 데몬 재살해,
수도사의 임프 자기 보호는 탐색하지 않는다. 대부·음유시인 트리거는 낮 처형 사망만 본다.
어릿광대·찻집 여인의 "처형됐지만 생존"은 이벤트로 표현할 수 없어 등장하지 않는다.

**역할 사전과는 별개다.** 사전(`src/data/roles.ts`)에는 3개 판본 전 역할 72종이 있고 사설
문제 편집기에서 무엇이든 고를 수 있지만, 위 목록(`SOLVER_ROLES`)에 없는 역할이 좌석에
배정되면 솔버가 검증을 거부한다 — 모르는 능력을 없는 셈 치고 세면 유일해 증명이 거짓이 된다.
능력을 구현할 때마다 이 목록에 추가한다.

### 2.5 정합성 검증 (핵심 요구사항)
- 모든 퍼즐은 **솔버가 전수 탐색으로 유일해임을 기계 증명**해야 한다.
- 퍼즐별 검증이 테스트 스위트로 돌며, 실패하면 배포 불가.
- 솔버는 개발용 도구로만 사용 (앱 UI에 노출하지 않음 — 스포일러 방지).
- 제작 흐름: Claude가 초안 생성 → 솔버 검증 통과 → 사용자 최종 검수.

## 3. 언어·표기

- UI 언어: 한국어.
- 역할명: **한국어(영어 병기)** — 예: "임프(Imp)", "탕녀(Scarlet Woman)".
- 역할명·에디션명은 **Pandemonium Institute 공식 한국어 번역**(`botc-translations`의 `game/ko.json`)을
  그대로 따른다. 임의 의역을 두지 않으며, `npm run rules:check`가 공식 표기와 대조해 차이를 보고한다.
- 확정 표기: Scarlet Woman = **탕녀** (공식 표기. 이전에 쓰던 "부정한 여인"은 2026-08-27 폐기).
- 진영 용어: Townsfolk=마을 사람, Outsider=외부인, Minion=하수인, Demon=데몬.
- 역할명은 **런타임에 수정하지 않는다**. 공식 번역에 고정하므로 앱 내 편집 기능을 두지 않는다 (§5.4).
- **도식 예외**: 타운스퀘어 토큰처럼 글자를 넣을 공간이 없는 도식 안에서는 **한글 단독**으로 적는다
  (지름 54px 토큰에 `세탁부(Washerwoman)`가 물리적으로 안 들어간다). 좌석을 누르면 나오는 카드에
  `한국어(영어)` 전체 표기가 그대로 있으므로 병기 원칙은 화면 단위로 지켜진다.

- 비주얼 톤: 모던한 레이아웃 + BotC 색감·서체 포인트(고딕/다크 무드 절충). 공식 아트 미사용.

## 5. 데이터·저장

### 5.1 퍼즐 데이터
- 문제 1개 = 리포지토리 내 TS 파일 1개 (`src/data/puzzles/`). 타입 스키마로 검증.
- 사람용 서술(`text`)과 솔버용 구조화 데이터를 병기.

### 5.2 풀이 기록 · 좌석 메모
- **localStorage**만 사용 (계정·DB 없음): 푼 문제, 첫 시도 성공 여부.
- 좌석 메모(표시 ✓ ? ✗ 악?, 대본에서 고른 역할 추측)도 같은 방식으로 **별도 키**에 담는다.
  **사용자라는 개념이 없다** — 계정도 세션도 기기 식별자도 없으므로 "누구의 메모인가"를 묻지 않고,
  같은 브라우저를 공유하지 않는 한 접속자끼리 섞이지 않는다.

### 5.3 정답 데이터
- 각 퍼즐 파일에 정답 그리모어(`solution`)와 서브 질문 정답 포함. 솔버 테스트가 유일해와 일치 여부를 검증.

### 5.4 역할명 변경 · 사용자 피드백
- 역할명은 공식 한국어 번역에 고정한다 (§3). 바꿀 일이 생기면 `src/data/roles.ts`를 직접 커밋한다.
- **앱 내 편집 기능은 두지 않는다.** 2026-08-27에 `/admin`과 `/api/admin/roles`를 제거했다.
  공식 표기 고정 원칙과 모순이었고, 그 기능만을 위해 repo 쓰기 토큰을 서버에 둘 이유가 없었다.
- 결과적으로 **앱은 서버 라우트도 비밀 값도 없는 완전 정적 사이트**다. 이 상태를 기본값으로 유지한다.
- 사용자 피드백(소감·오류 제보)은 **앱 밖의 외부 채널**로 받는다. 앱 안에 글쓰기 기능을 두면
  익명 쓰기 엔드포인트·스팸 대응·스포일러 노출·삭제 요청 대응이 한꺼번에 따라온다.
